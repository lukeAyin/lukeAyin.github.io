## 已确认的约束

- 目标是性能预测，调度与状态管理保持项目真实实现，不打桩、不另写调度逻辑。
- 算子耗时表等代价来源当前先打桩，未来替换为实测数据。
- 当前先验证执行代价、时间推进、完成事件与真实调度的衔接；预测准确率待真实数据校准。

## 每次学习的记录方式

1. 按路线选择本次问题，阅读真实源码并解释一个具体例子。
2. 将已讲解、已核对的行为写入相应功能文档；未确认的行为显式标注。
3. 将模块关系、接口、数据流和时间语义写入相应架构文档，并互相链接。
4. 有实验时记录配置、命令、输出和结论；纯源码阅读标注“未运行验证”。
5. 更新路线中的进度、文档链接和下次起点；涉及方案变化时同步讨论记录。

文档须区分生产实现、现有仿真原型和拟议设计。代码定位使用路径与符号名，记录核对的提交；行号可作为辅助，不单独作为依据。不因文档已创建就标记“已学习完成”。
